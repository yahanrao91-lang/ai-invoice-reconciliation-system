# 现场演示脚本（3～5 分钟）

> 目标：展示「真实 AI 提取 → 三单匹配 → 异常审核 → 报告导出」的完整闭环，全部在真实运行系统上操作。
> 前置：已配置 `.env`（`LLM_ENABLED=1` + DeepSeek 三项参数），演示数据已生成。

## 准备（提前 1 分钟）

```bash
cd "D:\eGG\Python学习咪咪\AI票据审核与采购对账系统"
.venv\Scripts\python.exe scripts\generate_demo_data.py   # 生成 7 组虚构演示文件
.venv\Scripts\python.exe -m streamlit run app.py        # 启动界面
```

打开浏览器 `http://localhost:8501`。

## 第 1 分钟：文档导入（三种格式真实处理）

1. 进入「文档管理」，选择 `demo_data/scenario_B/` 下三个文件：`PO_B.pdf`、`Invoice_B_1.xlsx`、`GRN_B_1.png`。
2. 任务名填「演示-数量异常」，点击「创建对账任务并处理」。
3. **强调**：PDF 走文本层、XLSX 走 openpyxl、PNG 走本地 RapidOCR，三种格式都被真实读取。

## 第 2 分钟：真实 AI 结构化提取 + OCR

1. 进入「AI 信息提取」，选择 `GRN_B_1.png`（收货单）。
2. 展示三层：**OCR 原始文本 → 结构化 JSON → 字段来源证据**。
3. **重点**：提取方式显示 `ai`（真实 DeepSeek `deepseek-flash`，不是离线规则）；PNG 是先 RapidOCR 识别、再由模型结构化。可指给面试官看 `method=ai` 与字段级证据。

## 第 3 分钟：三单匹配与异常

1. 进入「三单匹配」，展示 PO / 发票 / 收货三条明细与「匹配结果」表。
2. 指出发票数量 100、实收数量 95 的差异。
3. 展示异常记录：`QTY_OVER_RECEIPT`（HIGH，发票数量超过实际收货数量）。

## 第 4 分钟：人工审核（Human-in-the-Loop）

1. 进入「人工审核」，打开该异常，填写审核意见（例如「发票 100、实收 95，需核实 5 件差异」），点击「确认通过」。
2. 展示审核操作历史：操作、时间、审核意见、审核人，说明修正前后值留痕、可追溯到原始文件。

## 第 5 分钟：报告导出与总结

1. 进入「历史记录与报告」，点击「生成并下载 Excel 对账报告」。
2. 打开报告，展示 **7 张工作表**（对账总览 / 采购订单明细 / 发票明细 / 收货记录明细 / 三单匹配结果 / 异常记录 / 人工审核历史）与异常着色。
3. 一句话收尾：真实 AI 只做信息提取，金额与匹配用确定性规则引擎（Decimal）计算，异常不自动放行，全部可追溯。

## 收尾一句话

> 这套系统打通了「文件导入 → OCR/文本提取 → 真实 LLM 结构化 → 标准化校验 → 三单匹配 → 异常检测 → 人工审核 → 报告生成」的完整闭环：AI 负责理解、规则负责判定、人工负责终审。
